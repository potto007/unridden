# Why other local decision projects appear in recent YouTube videos

Checked September 27, 2026. This is a bounded comparison of discoverable videos and public launch material, **not** a causal study of YouTube recommendations or creator selection. No Unridden video was confirmed by the separate exact-name, former-name, repository, Shorts, and indexed-caption searches; that means *none found*, not *none exists*. YouTube search can miss new, unlisted, and caption-only mentions.

## Sample and method

I inspected the top 15 YouTube relevance results for each of `Kev Jev decision model`, `Laya Jev decision model`, `SemIf Jev`, `rizzo flow jev`, `jev local decision`, and `local decision model open source`, then checked candidate publication dates. I selected eight long-form videos dated September 20–27 that named at least one project in the [open-model survey](open-model-survey.md) or [broader census](jev-landscape-2026-09-27.md), plus one linked Short. This is a purposeful sample of presentation patterns, not a count of all coverage or a controlled comparison of channels. Titles, dates, descriptions, chapter markers, and links below were read from the videos' public YouTube metadata. Full captions became rate-limited, and a direct segment download was refused, so a chapter marker records the creator's description of that segment, not an independently viewed or transcribed moment. Claims in videos about performance remain their creators' claims.

For the three **external reviewer channels above the reach cut** (Sam, Cloud Codes, GitButler), the union of substantially reviewed named decision projects is **eight**: Kev, Laya, SemIf, Bespoke Nimble, Mapika Decider, Von, NanoJev, and Alex Wortega/openjev. **Three of eight** have “Jev” in their current official project/model name *or* repo/model slug: SemIf (`SemIf-OpenJev` slug, but not current displayed name), NanoJev, and Alex Wortega/openjev. Counting displayed names alone makes it **two of eight**. Omar's uncertain-affiliation Laya video would add no new project to that union. Sam also has a dedicated [DiffusionGemma/vLLM pull-request segment](https://github.com/vllm-project/vllm/pull/57250); it is excluded from this decision-project denominator because the linked artifact is a structured-generation integration, not a separately identifiable released Jev-like decision project. If counted as a ninth named model/segment, it does **not** contain “Jev” either.

Thus the claim that independently covered alternatives all borrow Jev in their **official names** is false in this bounded sample. Seven of the eight **video titles** use “Jev”, but title wording belongs to the uploader and is not project-name evidence; [Omar's Laya title](https://www.youtube.com/watch?v=P4hJikU_PYA) is the exception. [Rizzo's author-made video](https://www.youtube.com/watch?v=Qf5zGse6ii4) shows a creator can use a Jev comparison in a title and tagline while retaining a distinct project name, but it does not count as independent pickup. Search queries deliberately favored Jev-related coverage, so neither the fraction nor the title pattern estimates the wider YouTube ecosystem or proves a causal naming effect. The defensible Unridden experiment is a truthful “local Jev-like decisions” descriptor in searchable metadata and demo material, while keeping its community identity.

## Repeated patterns and Unridden's public surface

**A familiar search label opens the door.** Seven of the eight selected long-form titles say “Jev”; most also promise a local alternative, comparison, setup, or answer to a concrete question. Unridden's [Reddit launch](https://www.reddit.com/r/LLMDevs/comments/1wn11qp/riderless_a_decision_api_on_gemma_4_26ba4b_that/) mentions Jev inside the post, while its title led with the former name, a model identifier, and one 5090. The [public GitHub description](https://github.com/potto007/unridden) accurately says what the API does but does not include “Jev-like” or “System One”. YouTube exact-name searches returned unrelated horses, bikes, waves, and a different “Unridden” tool; project-qualified searches found no video. A query match may aid discovery, but these observations do not show whether any creator encountered Unridden.

**A visual use case makes the method legible.** RUNTIME's support workflow, GitButler's Tetris/settings demos, and Rizzo's Snake/playground each put a decision in a recognizable application and link inspectable materials. Unridden has a clear JSON hello request and diagrams, and [Tetris results](../results/full-depth-snapshots.md), but the public README currently links neither a runnable Tetris controller nor video/recording. The Tetris result table alone does not reveal what the controller computed versus what the model decided. That distinction matters: GitButler's demo explicitly says its code computes candidate landing features. The proposed Unridden follow-up should show the same boundary honestly.

**Viewers can see a first run and a realistic footprint.** Laya's [package, CLI, playground, and browser demo](https://github.com/NandhaKishorM/laya) and Kev's [browser tryout and four sizes](https://github.com/jaredpalmer/kev) give reviewers quick ways to test. SemIf offers a [browser replay](https://github.com/TheoLeeCJ/SemIf-OpenJev); Rizzo's site foregrounds a [playground and Snake](https://rizzo-ai-academy.github.io/rizzo-flow/). As checked on September 27, Unridden's **public** README still foregrounds the 26B model, roughly 18 GiB GPU headroom, and a 17 GB download. This is a *presentation issue, not a universal product requirement*: Unridden has a tested 5.13 GB E4B path and a separate [matched quality/latency report](../results/gemma4-e4b-vs-26b-usecases.md). An E4B-first README is present locally but was not on public `main` at this check. Linux/WSL support remains narrower than some alternatives, but a GPU-heavy Laya walkthrough and Kev's larger-model demos also drew coverage; hardware alone does not explain selection.

**Comparison material becomes a video outline.** Sam's roundup uses JevBench; RUNTIME publishes a small frozen comparison with failures; GitButler publishes its demo repository; the Japanese reviewer gives a shared test population and a Short. Unridden's [seven-suite comparison](../results/open-model-comparison.md) is detailed and candid, but it is authored for Unridden, synthetic, and not a matched hosted-Jev test. The [JevBench board](https://github.com/fstandhartinger/jevbench) currently has no Unridden row. This may make inclusion in benchmark-led roundups harder, though no creator gave that reason. The safe next claim is a bounded result on the existing suites, not “smarter/faster than Jev”.

**Timing explains some, not all, exclusions.** Unridden's [public repository](https://api.github.com/repos/potto007/unridden) was created late on September 21. Sam's September 20 roundup necessarily predates it; the September 21 videos may also have been planned earlier. Later September 22–26 reviews could have found it, but the sample provides no evidence about their discovery process, editorial deadline, pitches, or sponsorships. Rizzo's author-made video and Sam's disclosed compute sponsor cannot be generalized into a creator-outreach story for other projects.

## Highest-leverage changes to test

1. **Publish the E4B-first entry point already prepared locally.** Put the 5.13 GB route, exact first-answer steps, platform limits, and measured E4B-versus-26B tradeoff on public `main`; keep the 26B route available. This fixes a verified public documentation mismatch, while avoiding an unqualified minimum-VRAM promise. Measure first-run completion and questions from readers afterward.
2. **Release one inspectable, short visual demo package.** Use actual Unridden Tetris footage or another practical decision workflow, accompanied by its controller source, pinned model/configuration, same-seed replay inputs, a short clip or GIF, and a one-page explanation of which choices the model makes. Label request timing separately from full-move timing and show failures or mixed seeds. GitButler's [Tetris code](https://github.com/schacon/jev-tests) and Rizzo's [Snake playground](https://github.com/Rizzo-AI-Academy/rizzo-flow#playground-and-snake) show why this form is easy to demonstrate. Do not imply the present Tetris results can be reproduced from the repository until the controller is available.
3. **Create a reviewer-ready comparison page.** Give one plain-language question, a reproducible install or replay, a few representative outputs, exact hardware, and direct links to the full comparison and limitations. Add a JevBench public-set run as a separate external check, then seek an evaluator-run sealed score if warranted. Report accuracy, validity, calibration, and latency separately. The public set is not an official sealed score, and neither it nor Unridden's own suites justify hosted-Jev superiority.
4. **Make independent-project terminology discoverable.** Where accurate, put “local Jev-like typed decisions” and “no generated tokens” near the repository description, README opening, and demo title, with explicit non-affiliation. Keep Unridden as the community identity. Recheck YouTube/GitHub search visibility and referral traffic after publication; no present evidence proves terminology alone will change pickup.

No one was contacted. No video or Reddit post was created, and no competitor claim was promoted to a measured Unridden comparison.
